# edu-api

Бэкенд образовательной платформы по программированию: NestJS + Prisma 7 + PostgreSQL.
Отдаёт REST API для `edu-web` и импортирует контент из `edu-content`.

Бизнес-правила платформы (всегда в контексте):
@docs/DOMAIN-SHARED.md

## Документация

| Файл | Когда читать |
|---|---|
| `docs/ARCHITECTURE-BACKEND.md` | Перед любой задачей. Раздел 6 — каталог эндпоинтов с `operationId` |
| `docs/ROADMAP-BACKEND.md` | Тексты задач и порядок работ |
| `docs/CONTENT-FORMAT-SHARED.md` | Задачи, связанные с импортом контента |

## Команды

```bash
pnpm install
docker compose up -d          # postgres + mailpit (письма: http://localhost:8025)
pnpm prisma migrate dev       # применить миграции
pnpm prisma generate          # сгенерировать клиент в src/generated/prisma
pnpm prisma db seed           # администратор из env + демо-данные
pnpm dev                      # API :3000, Swagger /api/docs, JSON /api/docs-json
pnpm test                     # юнит-тесты
pnpm test:e2e                 # e2e (база edu_test)
pnpm lint && pnpm typecheck
pnpm content:import <путь>    # импорт контента (после API-10)
```

## Главные правила

Подробные правила лежат в `.claude/rules/` и подгружаются сами, когда ты работаешь с соответствующими файлами. Короткая версия, которая действует всегда:

1. **OpenAPI — это контракт с фронтендом.** У каждого эндпоинта должны быть `operationId` из `docs/ARCHITECTURE-BACKEND.md` (раздел 6), DTO ответа и описанные коды ошибок.
2. **Модели Prisma наружу не отдаются.** Ответ всегда собирается функцией маппинга в DTO. `passwordHash`, `tokenHash` и `Exercise.solution` не попадают в ответы.
3. **Все проверки доступа — только через `AccessService`.** Правила доступа живут в `access.rules.ts`.
4. **Ошибки — только коды из `DOMAIN.md`** через `AppException`. Новый код сначала добавляется в `DOMAIN.md`.
5. **Данные пользователя фильтруются по `userId` из сессии**, никогда по id из тела запроса.
6. **Одна задача — одна миграция.** Применённые миграции не редактируются.
7. **Бизнес-правила покрываются юнит-тестами, аутентификация и права — e2e-тестами.**
8. **Функции будущих версий не делаются**, пока их нет в задаче. Новые зависимости добавляются только при реальной необходимости.
9. **Недостающие решения.** Если в документации нет нужного решения, выбери самый простой вариант и запиши его в PR в разделе «Принятые решения».
10. **Язык.** Код, имена и комментарии в коде — на английском. Описание PR — на русском.

## Скиллы

| Скилл | Когда использовать |
|---|---|
| `nest-feature` | Новый модуль, эндпоинт или изменение существующего эндпоинта |
| `prisma-change` | Любое изменение `prisma/schema.prisma` |
| `api-e2e-test` | Написание или исправление e2e-тестов |
| `pr-ready` | Всегда перед созданием PR |

## Рабочий процесс

- Ветка называется `task/<ID>` (например, `task/API-03`), на задачу — один PR.
- Сообщения коммитов: `feat(auth): add session guard`, `fix(catalog): …`, `test(access): …`.
- Если в ходе задачи меняется эндпоинт, в том же PR обновляется таблица в `docs/ARCHITECTURE-BACKEND.md`, раздел 6.
- Если меняется бизнес-правило, в том же PR обновляется `docs/DOMAIN-SHARED.md`, а в описании PR пишется, что копию в `edu-web` тоже нужно обновить.
