# Сервисы и правила доступа

- **Доступ.** Любое решение «можно ли пользователю X сделать Y с уроком или курсом» принимает `AccessService`. Правила не дублируются в других сервисах, даже в виде «быстрой проверки».
- **Чистые правила.** `access.rules.ts` содержит только чистые функции без Prisma и Nest: на вход данные, на выход решение. `AccessService` загружает данные и вызывает их.
- **Изменение правил.** Сначала обновляется `docs/DOMAIN-SHARED.md` (раздел 5), затем табличные тесты, затем код. Если в `DOMAIN.md` правила нет, его нельзя придумывать в коде.
- **Переводы.** Перевод выбирается только через `pickTranslation` из `src/common/translations.ts`. Публично видны только `PUBLISHED`; при отсутствии перевода делается откат на `ru` с `isFallback: true`.
- **Изоляция данных.** Запросы к данным пользователя всегда содержат `where: { userId }`, где `userId` взят из сессии.
- **Транзакции.** Несколько связанных записей (завершение урока после сдачи, изменение порядка, импорт) выполняются в `prisma.$transaction`.
- **Ошибки.** Бросаются только `AppException` с кодами из `src/common/error-codes.ts`. Сырые ошибки Prisma не уходят наружу: например, `P2002` превращается в осмысленный код вроде `EMAIL_TAKEN`.
- **Выборка полей.** В `select` запрашиваются только нужные поля, особенно в каталоге. `solution` выбирается только в эндпоинте эталона и в админке.
