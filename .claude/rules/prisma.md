# Prisma 7 и миграции

- **Подключение.** Строка подключения задаётся в `prisma.config.ts`, а не в `schema.prisma`. `PrismaClient` создаётся с `@prisma/adapter-pg` и импортируется из `src/generated/prisma`. Не используй примеры для `prisma-client-js` из старых версий.
- **Порядок изменения схемы** описан в скилле `prisma-change`. Коротко: схема → `pnpm prisma migrate dev --name <snake_case>` → проверка SQL → `pnpm prisma generate` → сид и маппинги.
- **Одна задача — одна миграция** с понятным именем: `add_problem_reports`, а не `update`.
- **Применённые миграции не редактируются никогда.** Ошибка исправляется новой миграцией.
- **Разрушающие изменения** (удаление или переименование колонки или таблицы, смена типа) делаются в два шага: добавить новое и перенести данные, а удалить старое — отдельной задачей позже. Такое изменение описывается в PR.
- **Сид идемпотентен:** повторный запуск не создаёт дублей (upsert по уникальным полям).
- **`src/generated/prisma` не редактируется вручную.**
