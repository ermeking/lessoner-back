# Модуль или эндпоинт в edu-api

Фронтенд получает типы и хуки из OpenAPI через Kubb. Поэтому эндпоинт считается готовым, только когда он правильно работает **и** правильно описан. Шаблоны кода лежат в `references/templates.md`: открой его, когда дойдёшь до шага 3.

## Шаг 1. Сверься с документацией

- Найди эндпоинт в `docs/ARCHITECTURE-BACKEND.md`, раздел 6: метод, путь, доступ, `operationId`. Если его там нет, а задача его требует, добавь строку в таблицу в этом же PR.
- Проверь, какие правила из `docs/DOMAIN-SHARED.md` затрагивает эндпоинт (доступ, прогресс, роли) и какие коды ошибок он может вернуть.

## Шаг 2. Выбери место

- Существующий модуль, если эндпоинт относится к его зоне (таблица модулей в `docs/ARCHITECTURE-BACKEND.md`, раздел 5).
- Новый модуль — только если в архитектуре его нет и задача явно это требует. Создай `src/modules/<name>/` со стандартными файлами и подключи модуль в `app.module.ts`.
- Проверь зависимости: `catalog` и `learning` не зависят друг от друга, общее выносится в `access` или `common`.

## Шаг 3. Напиши код по шаблонам

Порядок: DTO запроса → DTO ответа и функция маппинга → сервис → контроллер.

1. **DTO запроса.** Для каждого поля нужны валидация class-validator и `@ApiProperty`. Для enum из Prisma указывай `enumName`.
2. **DTO ответа** с суффиксом `ResponseDto` и функция `toXxxResponse(entity)`. Здесь решается, что уходит наружу; секретные поля не попадают в DTO никогда.
3. **Сервис.** Бизнес-логика, Prisma, проверки через `AccessService`, ошибки через `AppException`. Данные пользователя фильтруются по `userId` из сессии.
4. **Контроллер.** Декоратор доступа (`@Public`, `@OptionalAuth`, `@Roles` или ничего для «нужен вход»), `@ApiOperation({ operationId })`, декоратор ответа, `@ApiErrors(...)`, при необходимости `@Throttle`.

## Шаг 4. Тесты

- **Юнит-тест** на новую бизнес-логику, если она есть (особенно чистые функции).
- **e2e-тест** на каждый эндпоинт: успешный сценарий, отказ без входа или с неправильной ролью, основной сценарий ошибки. Как писать — скилл `api-e2e-test`.

## Шаг 5. Проверь контракт

1. `pnpm dev` → открой `/api/docs-json` и найди свой `operationId`.
2. Убедись, что типы ответа не `object` и не `any`, что enum имеют имена, а коды ошибок перечислены.
3. Если меняется существующий ответ, в описании PR пиши: «фронтенду нужно перегенерировать клиент (`pnpm api:gen`)».

## Частые ошибки

- Вернуть из контроллера результат `prisma.xxx.findUnique` напрямую: наружу утекут лишние поля.
- Проверить доступ в контроллере, а не через `AccessService`.
- Забыть `@ApiErrors`: фронтенд тогда не знает, какие ошибки обрабатывать.
- Использовать `@Body() body: any` или DTO без декораторов: `whitelist` вырежет все поля.
- Дать эндпоинту `operationId`, которого нет в таблице архитектуры.
