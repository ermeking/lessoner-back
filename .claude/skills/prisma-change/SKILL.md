# Изменение схемы БД (Prisma 7)

Схема — фундамент, общий для всех модулей. Ошибка в миграции на продакшне стоит дороже ошибки в коде: её нельзя просто откатить, поэтому действуй по шагам.

## Перед изменением

1. Убедись, что изменение нужно для задачи. Модели будущих версий (`Payment`, `Quiz`, `Project`) не добавляются заранее.
2. Проверь соглашения из `docs/ARCHITECTURE-BACKEND.md`, раздел 8:
   - UUID-идентификаторы (`@id @default(uuid()) @db.Uuid`), внешние ключи тоже с `@db.Uuid`;
   - деньги в `Int` (сомы), длинные тексты в `@db.Text`;
   - тексты контента — только в таблицах `*Translation` с `@@unique([<сущность>Id, locale])`;
   - у связей `onDelete` выбран осознанно: `Cascade` для дочерних данных, `Restrict` там, где удаление должно блокироваться (сдачи, прогресс);
   - индексы на полях, по которым идут частые запросы и сортировки.

## Шаги

```bash
# 1. Отредактировать prisma/schema.prisma
# 2. Создать миграцию с понятным именем (snake_case, по сути изменения)
pnpm prisma migrate dev --name add_problem_report_locale
# 3. Сгенерировать клиент (в Prisma 7 делай это явно)
pnpm prisma generate
# 4. Проверить типы и тесты
pnpm typecheck && pnpm test && pnpm test:e2e
```

После шага 2 **открой сгенерированный `migration.sql` и прочитай его.** Проверь:

- нет ли неожиданных `DROP` — частая причина: переименование поля Prisma понимает как удаление и создание;
- как миграция поведёт себя на таблице, где уже есть данные: новое обязательное поле без `@default` сломает миграцию на непустой таблице.

## Разрушающие изменения

Переименование, удаление или смена типа колонки делается в два шага, чтобы не потерять данные:

1. **Эта задача:** добавить новое поле (необязательное или с default) и перенести данные SQL-командой в той же миграции (её можно дописать вручную до применения). Код переходит на новое поле.
2. **Отдельная задача позже:** удалить старое поле.

В PR такое изменение описывается в разделе «Принятые решения».

## Если миграция уже применена где-то, кроме твоей машины

Не редактируй её. Создай новую миграцию, которая исправляет ошибку.

## После изменения

- Обнови `prisma/seed.ts`, если новая сущность нужна в демо-данных. Сид должен остаться идемпотентным (upsert).
- Обнови DTO и функции маппинга, которые затрагивает изменение.
- Обнови фабрики в `test/factories.ts`.
- Если изменение добавляет понятие, которого нет в `docs/DOMAIN-SHARED.md` (раздел 2), добавь его туда.

## Prisma 7 — что отличается от старых примеров

- `url` в `datasource` не пишется: подключение задаётся в `prisma.config.ts`.
- Генератор — `prisma-client` с `output = "../src/generated/prisma"`; импорт идёт из `src/generated/prisma/client`, а не из `@prisma/client`.
- `PrismaClient` создаётся с драйвер-адаптером: `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })`.
- При сомнениях проверь актуальную документацию Prisma 7 и не копируй код из старых статей.
