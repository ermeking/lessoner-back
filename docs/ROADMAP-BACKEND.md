# Роадмап `edu-api`

> План работ бэкенда. Архитектура — `docs/ARCHITECTURE-BACKEND.md`, бизнес-правила — `docs/DOMAIN-SHARED.md`.
> `operationId` всех эндпоинтов берутся из `docs/ARCHITECTURE-BACKEND.md`, раздел 6.
> Фронтенд (`edu-web`) и контент (`edu-content`) идут параллельно; точки, где они ждут бэкенд, указаны у каждой вехи.

## Как отдавать задачу агенту

```
Ты работаешь в репозитории edu-api.
Прочитай CLAUDE.md, docs/DOMAIN-SHARED.md и docs/ARCHITECTURE-BACKEND.md.
Выполни задачу <ID> из docs/ROADMAP-BACKEND.md — полный текст ниже. Работай в ветке task/<ID>.
Используй скиллы из .claude/skills, когда они подходят. Перед PR выполни скилл pr-ready.

<текст задачи>
```

Одна задача — одна сессия агента и один PR. Следующая задача начинается после проверки PR по критериям «Готово, когда».

## Веха 0. Фундамент

**Цель вехи:** API запускается, публикует OpenAPI и содержит демо-данные.

**Связь с другими репозиториями:** После вехи фронтенд может генерировать клиент (WEB-02).

### API-01 · Каркас edu-api

**Цель:** рабочий каркас бэкенда, на котором строятся все остальные задачи.

**Сделать:**
- NestJS-проект на pnpm, TypeScript в strict-режиме.
- `ConfigModule` с валидацией env через zod: при неверных переменных приложение падает на старте с понятным сообщением.
- Prisma 7: `prisma.config.ts`, `@prisma/adapter-pg`, `PrismaService`. Схему пока не переносить (это API-02).
- Глобальный префикс `/api`, версия `v1`.
- Swagger: UI на `/api/docs`, JSON на `/api/docs-json`, CLI-плагин `@nestjs/swagger`.
- Логирование через nestjs-pino.
- Глобальный `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`).
- Фильтр исключений, который всегда отдаёт ошибки в формате `{ code, message }`; файл `src/common/error-codes.ts`.
- `GET /api/v1/health` → `{ status: 'ok', db: 'ok' }` с реальной проверкой БД.
- `docker-compose.yml` для разработки: postgres и mailpit.
- Многоэтапный `Dockerfile`, ESLint + Prettier, Jest + supertest (стандарт NestJS).
- GitHub Actions: lint, typecheck, test, build.
- `.env.example` и README с инструкцией запуска.

**Готово, когда:**
- [ ] `docker compose up -d && pnpm dev` поднимает API, health отвечает 200.
- [ ] `/api/docs-json` отдаёт валидную OpenAPI-спецификацию.
- [ ] При отсутствии `DATABASE_URL` приложение падает с понятной ошибкой.
- [ ] CI зелёный.

### API-02 · Схема БД и сид

**Зависит от:** API-01

**Цель:** схема БД из пакета документов и демо-данные для разработки.

**Сделать:**
- Перенести `prisma/schema.prisma` из пакета документов и создать первую миграцию `init`.
- `prisma/seed.ts`, идемпотентный:
  - администратор из `ADMIN_EMAIL` / `ADMIN_PASSWORD`;
  - направление `frontend`;
  - бесплатный опубликованный курс `demo-js`: 1 модуль, 2 урока, по одному заданию в каждом (starter, solution и tests по `CONTENT_FORMAT.md`), русские тексты в статусе `PUBLISHED`; у первого урока есть ещё и английский перевод, чтобы проверять откат на русский;
  - платный опубликованный курс `demo-paid` (цена 100): 2 урока, первый с `isPreview`.

**Готово, когда:**
- [ ] `migrate` + `seed` на пустой БД проходят без ошибок.
- [ ] Повторный `seed` не создаёт дублей.

## Веха 1. Аккаунты

**Цель вехи:** полный цикл аккаунта: регистрация, вход, письма, Google, профиль.

**Связь с другими репозиториями:** Открывает WEB-03 (страницы аккаунта).

### API-03 · Регистрация, вход, сессии, роли

**Зависит от:** API-02

**Цель:** аутентификация по `docs/ARCHITECTURE-BACKEND.md`, раздел 7; коды ошибок — `docs/DOMAIN-SHARED.md`, раздел 6.

**Сделать:**
- Эндпоинты:
  - `POST /auth/register` `{ name, email, password, locale }` — создаёт пользователя, сессию и ставит куку;
  - `POST /auth/login`, `POST /auth/logout`, `POST /auth/logout-all`;
  - `GET /auth/me` → `{ id, name, email, role, locale, emailVerified }` или 401.
- Глобальный `SessionGuard` с декораторами `@Public()` и `@OptionalAuth()`, а также `@Roles()` + `RolesGuard` и `@CurrentUser()`.
- Продление сессии, если с `lastUsedAt` прошло больше суток.
- Rate limit на `/auth/*` через `@nestjs/throttler`.
- Middleware проверки `Origin` для изменяющих запросов.
- Заблокированный пользователь получает 403 `USER_BLOCKED`, его сессии удаляются.
- Коды ошибок: `EMAIL_TAKEN`, `INVALID_CREDENTIALS`, `USER_BLOCKED`, `UNAUTHORIZED`, `FORBIDDEN`.

**Не делать:** письма (API-04), Google (API-05).

**Готово, когда (e2e-тесты):**
- [ ] Регистрация → `me` → выход → `me` возвращает 401.
- [ ] Неверный email и неверный пароль дают одинаковый ответ `INVALID_CREDENTIALS`.
- [ ] Повторная регистрация с тем же email даёт `EMAIL_TAKEN`.
- [ ] Кука `httpOnly`, `SameSite=Lax`; в БД хранится хеш, а не токен.
- [ ] POST с чужим `Origin` даёт 403.

### API-04 · Письма: подтверждение email и сброс пароля

**Зависит от:** API-03

**Сделать:**
- `MailModule` на nodemailer (SMTP). Шаблоны писем на `ru`, `ky`, `en`, язык берётся из `user.locale`.
- Одноразовые токены `UserToken` (в БД хранится хеш): подтверждение email действует 24 часа, сброс пароля — 1 час.
- Эндпоинты:
  - `POST /auth/verify-email/send` (для вошедшего) и `POST /auth/verify-email` `{ token }`;
  - `POST /auth/password/forgot` `{ email }` — всегда отвечает 204, чтобы не раскрывать, есть ли такой email;
  - `POST /auth/password/reset` `{ token, password }` — меняет пароль и удаляет все сессии пользователя.
- После регистрации автоматически отправляется письмо подтверждения.
- Ссылки в письмах: `APP_URL/{locale}/verify-email?token=…` и `APP_URL/{locale}/reset-password?token=…`.

**Готово, когда:**
- [ ] Письма на всех трёх языках видны в mailpit.
- [ ] Истёкший или уже использованный токен даёт `TOKEN_INVALID`.
- [ ] После сброса пароля старые сессии не работают.

### API-05 · Вход через Google

**Зависит от:** API-03

**Сделать** (по `docs/ARCHITECTURE-BACKEND.md`, раздел 7):
- `GET /auth/google?redirect=<путь>`: принимается только относительный путь, это защита от open redirect.
- `GET /auth/google/callback`: `state` хранится в куке 10 минут, email от Google должен быть подтверждён. Пользователь создаётся или привязывается, создаётся сессия, затем редирект.
- Для существующего аккаунта с неподтверждённым email: email помечается подтверждённым, пароль сбрасывается.
- Реализация через `openid-client` или `passport-google-oauth20`.

**Готово, когда (e2e с моком Google):**
- [ ] Вход нового пользователя работает.
- [ ] Вход существующего пользователя привязывает Google к его аккаунту.
- [ ] Сценарий с неподтверждённым аккаунтом: пароль сброшен, email подтверждён.
- [ ] Подменённый `state` отклоняется.

### API-06 · Профиль пользователя

**Зависит от:** API-03

**Сделать:**
- `PATCH /users/me` `{ name?, locale? }`.
- `POST /users/me/password` `{ currentPassword?, newPassword }`: пользователю, который входит только через Google, текущий пароль не нужен. После смены удаляются все сессии, кроме текущей.

**Готово, когда:**
- [ ] Написаны e2e-тесты на оба эндпоинта, включая неверный текущий пароль (`INVALID_CREDENTIALS`).

## Веха 2. Каталог

**Цель вехи:** правила доступа и публичное чтение контента на трёх языках.

**Связь с другими репозиториями:** Открывает WEB-05 и WEB-06 (публичные страницы и урок).

### API-07 · AccessService и публичный каталог

**Зависит от:** API-06

**Сделать:**
- Модуль `access`: чистые функции правил в `access.rules.ts` и `AccessService` по `docs/DOMAIN-SHARED.md`, раздел 5 (устройство — `docs/ARCHITECTURE-BACKEND.md`, раздел 5): `canReadLesson`, `getLessonState`, `canSubmit`, `canSeeSolution`, `getCourseLessonOrder`.
- Хелпер `pickTranslation` с откатом на опубликованный русский и флагом `isFallback`.
- Эндпоинты каталога с `@OptionalAuth` (работают для гостя, но учитывают вошедшего пользователя). Каждый принимает `?locale=`:
  - `GET /catalog/tracks` — опубликованные направления;
  - `GET /catalog/tracks/:slug` — направление и карточки курсов (title, shortDescription, level, access, price, lessonsCount);
  - `GET /catalog/courses/:slug` — курс и программа: модули → уроки (title, slug, minutes, isPreview), `state` каждого урока для вошедшего, `hasAccess`;
  - `GET /catalog/courses/:courseSlug/lessons/:lessonSlug` — урок: title, body, isFallback, prev/next, state и задания (id, title, statement, hints, starterCode, tests, **без solution**). Для платного урока без доступа — 403 `COURSE_NOT_PURCHASED`;
  - `GET /catalog/sitemap` — slug'и публично доступных курсов и уроков для sitemap.

**Готово, когда:**
- [ ] Юнит-тесты `AccessService` покрывают всю таблицу 5.2 и все правила 5.3 из `docs/DOMAIN-SHARED.md`.
- [ ] e2e на демо-данных: гость читает бесплатный урок; гость не читает обычный урок платного курса, но читает превью.
- [ ] Запрос урока на `en` без английского перевода возвращает русский текст с `isFallback: true`.
- [ ] `solution` нет ни в одном публичном ответе.

## Веха 3. Практика

**Цель вехи:** сдачи, прогресс по порядку, подсказки, эталоны и дашборд.

**Связь с другими репозиториями:** Открывает WEB-09 и WEB-10 (задания и кабинет).

### API-08 · Сдачи, прогресс, подсказки, эталоны

**Зависит от:** API-07

**Сделать** (все эндпоинты только для вошедших пользователей):
- `POST /learning/exercises/:id/submissions` `{ code, passed, testsPassed, testsTotal }` → `{ lessonCompleted, nextLesson? }`. Принимаются и успешные, и неуспешные сдачи: неуспешные нужны для статистики. Ошибки: `LESSON_LOCKED`, `COURSE_NOT_PURCHASED`. Лимит кода 50 КБ, rate limit.
- `POST /learning/lessons/:id/complete` — для уроков без заданий.
- `POST /learning/exercises/:id/hints` `{ level }` — запоминает максимальный открытый уровень подсказки.
- `GET /learning/exercises/:id/solution` — эталон или 403 `SOLUTION_LOCKED`.
- `GET /learning/lessons/:id/state` — по каждому заданию урока: пройдено ли, сколько подсказок открыто, последний отправленный код.
- `GET /learning/dashboard` — `continue` (курс и урок) и список курсов с прогрессом (завершено уроков из общего числа, процент, дата последней активности).

**Готово, когда:**
- [ ] Юнит-тесты: правила порядка, завершение урока, правила выдачи эталона.
- [ ] e2e: полное прохождение демо-курса от первого до последнего урока.

## Веха 4. Админка и контент

**Цель вехи:** управление контентом и переводами, импорт из edu-content, пользователи, обращения, статистика.

**Связь с другими репозиториями:** Открывает WEB-11 и WEB-12. API-10 требует готового CONTENT-01 (формат и пример курса).

### API-09 · Админ API: контент и переводы

**Зависит от:** API-07

**Сделать** (роли `REVIEWER` и `ADMIN`):
- CRUD направлений, курсов, модулей, уроков и заданий. В админке у задания видны `solution` и `tests`.
- Порядок элементов: `PUT …/order { ids: [] }`. Связи направление–курс, флаг `isPublished`.
- Валидация цены: у `FREE` курса цена 0, у `PAID` больше 0.
- Переводы:
  - `GET /admin/<сущность>/:id/translations/:locale` и `PUT` того же адреса;
  - `PATCH` статуса. Разрешённые переходы: `DRAFT → REVIEW → PUBLISHED`; снятие с публикации — `PUBLISHED → DRAFT`.
- Урок или задание, у которых есть сдачи, удалить нельзя: 409 `HAS_SUBMISSIONS`.
- `GET /admin/content/tree` — дерево контента с матрицей статусов переводов по языкам.

**Готово, когда (e2e):**
- [ ] `REVIEWER` может править контент, `STUDENT` получает 403.
- [ ] После публикации перевода он появляется в публичном API.

### API-10 · Импорт контента (CLI)

**Зависит от:** API-09, CONTENT-01

**Сделать:**
- `pnpm content:import <путь> [--course <slug>] [--dry-run] [--force]` строго по `docs/ARCHITECTURE-BACKEND.md` (раздел 10) и `docs/CONTENT-FORMAT-SHARED.md`.
- Схемы валидации файлов повторяют `edu-content/tools/check.mjs`. Если формат меняется, сначала меняется `CONTENT_FORMAT.md`.
- `contentHash` для пропуска неизменённого контента.
- Картинки копируются в `MEDIA_DIR`, ссылки в Markdown переписываются.
- Итоговый отчёт: создано, обновлено, пропущено, «есть в БД, но нет в файлах».

**Готово, когда:**
- [ ] Импорт `courses/_example` из edu-content проходит успешно.
- [ ] Повторный импорт без изменений ничего не меняет.
- [ ] Изменённый опубликованный урок без `--force` пропускается с предупреждением; с `--force` обновляется и остаётся `PUBLISHED`.
- [ ] Ошибка в одном файле отменяет импорт всего курса, а в сообщении указан путь к файлу.

### API-11 · Пользователи, обращения, статистика

**Зависит от:** API-09

**Сделать:**
- Пользователи (только `ADMIN`):
  - `GET /admin/users` с поиском и пагинацией;
  - `GET /admin/users/:id` — прогресс и доступы;
  - блокировка и разблокировка;
  - `POST /admin/users/:id/grants` `{ courseId, note }` (источник `MANUAL`) и отзыв доступа.
- Обращения:
  - `POST /reports` `{ lessonId, exerciseId?, message, locale }` — только для вошедших, не больше 5 в час;
  - `GET /admin/reports?status=` и `PATCH /admin/reports/:id` (роли `REVIEWER` и `ADMIN`).
- Статистика (роли `REVIEWER` и `ADMIN`):
  - `GET /admin/stats/exercises` по `docs/ARCHITECTURE-BACKEND.md`, раздел 11, с фильтром по курсу и сортировкой по доле успеха;
  - `GET /admin/stats/overview` — пользователи всего и за 7 дней, сдачи за 7 дней, завершённые уроки.

**Готово, когда:**
- [ ] Юнит-тесты на расчёт статистики.
- [ ] e2e на права доступа по ролям.

**Цель вехи:** продакшн-окружение с HTTPS и бэкапами.

### INFRA-01 · Продакшн-развёртывание

**Зависит от:** API-11 (фактически — перед запуском). Репозиторий: `edu-api/deploy/`.

**Сделать:**
- `docker-compose.prod.yml`: caddy (автоматический HTTPS), web, api, postgres (с томом), том media.
- `Caddyfile` по `docs/ARCHITECTURE-BACKEND.md`, раздел 15: `/api/*` → api, `/media/*` → файлы с кешированием, всё остальное → web.
- `prisma migrate deploy` при старте api.
- Скрипт бэкапа: `pg_dump`, ротация за 14 дней, выгрузка за пределы сервера (команду выгрузки задаёт владелец через переменную).
- Сборка образов в GitHub Actions и публикация в GitHub Container Registry.
- `deploy/README.md`: первый запуск на чистом Ubuntu, обновление, откат, восстановление из бэкапа.

**Готово, когда:**
- [ ] Проект разворачивается на чистом VPS по инструкции.
- [ ] Восстановление из бэкапа проверено на практике.
