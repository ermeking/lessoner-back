# Формат контента (`edu-content`)

> **Общий документ.** Одинаковая копия лежит в `docs/` всех трёх репозиториев; меняется сначала в `edu-content`.
> Контракт между авторами контента (люди и агенты), импортом в `edu-api` и раннером в `edu-web`.
> Импорт валидирует каждый файл по этой спецификации и отказывается загружать курс с ошибками.

---

## 1. Структура репозитория

```
edu-content/
├─ glossary.yaml                        глоссарий терминов для переводов
├─ tools/
│  ├─ harness.js                        эталонная реализация API тестов (раздел 6)
│  └─ check.mjs                         проверка всего контента (раздел 9)
├─ tracks/
│  └─ frontend.yaml                     направление и порядок его курсов
└─ courses/
   └─ js-basics/                        slug курса
      ├─ course.yaml
      ├─ 01-first-steps/                модуль: NN-slug
      │  ├─ module.yaml
      │  ├─ 01-what-is-javascript/      урок: NN-slug
      │  │  ├─ lesson.yaml
      │  │  ├─ ru.md                    текст урока на русском (оригинал)
      │  │  ├─ ky.md                    перевод (может отсутствовать)
      │  │  ├─ en.md                    перевод (может отсутствовать)
      │  │  ├─ assets/                  картинки урока (необязательно)
      │  │  └─ exercises/
      │  │     └─ 01-hello-world/       задание: NN-slug
      │  │        ├─ exercise.yaml
      │  │        ├─ starter.js
      │  │        ├─ solution.js
      │  │        ├─ tests.js
      │  │        ├─ ru.md
      │  │        ├─ ky.md
      │  │        └─ en.md
      │  └─ 02-variables/
      └─ 02-.../
```

### Правила имён

Модули, уроки и задания лежат в папках вида `NN-slug`. Число задаёт порядок, slug — постоянный идентификатор.

- **slug.** Только латиница в нижнем регистре, цифры и дефис. Slug урока уникален в пределах курса, потому что он входит в URL.
- **Перенумерация.** Номер `NN` можно менять свободно: так меняется порядок.
- **Переименование.** Новый slug означает новую сущность: прогресс учеников по старому уроку останется у старого. Поэтому slug не переименовываем без крайней необходимости.
- **Удаление.** Удаление папки не удаляет урок из БД: импорт только сообщит о расхождении.

## 2. Направление — `tracks/<slug>.yaml`

```yaml
slug: frontend
icon: code            # имя иконки из набора интерфейса
position: 1
courses:              # порядок курсов в направлении; курс может быть в нескольких направлениях
  - intro-to-programming
  - js-basics
  - oop
  - git-basics
translations:
  ru:
    title: Frontend-разработка
    description: |
      Markdown-описание направления.
  ky:
    title: ...
    description: ...
  en:
    title: Frontend Development
    description: ...
```

## 5. Урок

### `lesson.yaml`

```yaml
isPreview: false      # для платных курсов: открыт ли урок без покупки
minutes: 15           # примерное время на урок
```

### `ru.md`, `ky.md`, `en.md`

```markdown
---
title: Что такое JavaScript
---

Текст урока в Markdown.
```

Какие элементы Markdown можно использовать:

| Элемент | Синтаксис |
|---|---|
| Заголовки | Только `##` и `###`; `#` зарезервирован под название урока |
| Код | Блоки с указанием языка: ` ```js `, ` ```bash `, ` ```html ` |
| Таблицы, списки, жирный, курсив, ссылки | Стандартный GFM |
| Заметка | `:::note` … `:::` |
| Совет | `:::tip` … `:::` |
| Предупреждение | `:::warning` … `:::` |
| Картинка | `![описание](./assets/scheme.png)` — файл лежит в `assets/` урока |

Сырой HTML запрещён: при рендере он вырезается.

## 6. Задание

### `exercise.yaml`

```yaml
runtime: js           # в v1 только js
```

### `starter.js` и `solution.js`

`starter.js` содержит стартовый код, который ученик видит в редакторе. `solution.js` — эталонное решение. Оно обязано проходить все тесты, это проверяет команда `npm run check` (раздел 9). Код общий для всех языков. Комментарии в стартовом коде пишем на английском или делаем минимальными, потому что они не переводятся.

### `ru.md`, `ky.md`, `en.md`

```markdown
---
title: Привет, мир
hints:
  - Намёк, без готового ответа.
  - Подход к решению.
  - Почти готовое решение.
---

Условие задания в Markdown. Обязательно указываем точное имя функции,
которую нужно написать, или точный текст, который нужно вывести.
```

Подсказок ровно три, в порядке от лёгкой к почти решению. Во всех языковых версиях одного задания число подсказок одинаковое.

### `tests.js`

Тесты выполняются в браузере в одной области видимости с кодом ученика, поэтому видят объявленные им функции и переменные.

```js
// ky можно не указывать, пока нет перевода: будет показан ru
test({ ru: 'Функция sum объявлена', en: 'Function sum is declared' }, () => {
  expect(typeof sum).toBe('function');
});

test(
  { ru: 'Складывает положительные числа', en: 'Adds positive numbers' },
  () => {
    expect(sum(2, 3)).toBe(5);
  }
);

test({ ru: 'Выводит приветствие', en: 'Prints the greeting' }, () => {
  expect(output()).toContain('Hello, World!');
});
```

API тестов:

| Функция | Что делает |
|---|---|
| `test(name, fn)` | Объявляет тест. `name` — объект `{ ru, ky?, en? }`; если нужного языка нет, берётся `ru`. `fn` может быть `async` |
| `expect(x).toBe(y)` | Строгое равенство (`Object.is`) |
| `expect(x).toEqual(y)` | Глубокое равенство объектов и массивов |
| `expect(x).toBeTruthy()` / `.toBeFalsy()` | Проверка на истинность |
| `expect(x).toContain(y)` | Элемент в массиве или подстрока в строке |
| `expect(fn).toThrow()` | Функция бросает ошибку |
| `expect(x).toBeCloseTo(y, digits?)` | Сравнение дробных чисел |
| `.not` | Отрицание: `expect(x).not.toBe(y)` |
| `output()` | Массив строк, выведенных через `console.log`, в порядке вывода |

Правила для тестов:

- **Первый тест проверяет наличие.** Для функций он проверяет, что функция объявлена (`typeof name === 'function'`). Так ученик видит понятную ошибку, а не `ReferenceError`.
- **Названия тестов понятны новичку.** Они описывают поведение: «Складывает отрицательные числа», а не «test 3».
- **Сообщения о несовпадении писать не нужно.** Их формирует раннер («Ожидалось 5, получено 4») на языке интерфейса.
- **Лимит времени.** Код ученика вместе с тестами выполняется не дольше 3 секунд.

## 7. Глоссарий — `glossary.yaml`

```yaml
- key: closure
  ru: замыкание
  ky: ...                      # решает редактор-носитель
  en: closure
  note: При первом упоминании давать английский термин в скобках.
- key: promise
  ru: промис
  ky: ...
  en: promise
```

Переводчики и агенты обязаны использовать термины строго по глоссарию. Новый термин сначала добавляется в глоссарий, потом используется в уроках.

## 8. Статусы и импорт

Импорт выставляет переводам статус `REVIEW`, а после проверки их публикуют в админке. Если перевода на каком-то языке ещё нет, файл просто не создаётся, и сайт покажет русскую версию с плашкой «Перевод готовится». Подробнее о поведении импорта — `edu-api/docs/ARCHITECTURE-BACKEND.md`, раздел 10.

## 9. Проверка контента — `npm run check`

Скрипт `tools/check.mjs` проверяет весь репозиторий и запускается перед каждым коммитом и в CI:

- структура папок и имена соответствуют разделу 1;
- все YAML и frontmatter проходят схему;
- в каждом `.md` есть `title`, а у заданий — ровно три подсказки;
- картинки из Markdown существуют в `assets/`;
- каждый `solution.js` проходит все свои тесты, а `starter.js` не проходит (иначе задание решено заранее).

Решения прогоняются через `tools/harness.js` в Node (модуль `vm`, таймаут 3 секунды).

`tools/harness.js` — единственная эталонная реализация API тестов. Раннер в `edu-web` использует копию этого файла. Если меняется API тестов, сначала меняется `harness.js` здесь, затем копия в `edu-web`.
